# Task 3 - Peering 구성과 검증

1. 허브 VNet → [피어링] → [추가]
2. **로컬 가상 네트워크** 쪽 이름 : `peer-hub-to-spoke-user**`  — 포털 문구가 "이 가상 네트워크"에서 **"로컬 가상 네트워크"로 바뀌었고**, 입력 순서도 화면 아래쪽에 있을 수 있습니다. 항목 위치보다 **이름이 어느 쪽을 가리키는지**를 보고 채우세요.
3. **원격 가상 네트워크** 쪽 이름 : `peer-spoke-to-hub-user**`
4. 원격 가상 네트워크로 스포크 VNet을 선택합니다.
5. 「로컬 가상 네트워크 피어링 설정」과 「원격 가상 네트워크 피어링 설정」에서 **양쪽 각각 위 두 개**를 켭니다 — ① 액세스 허용(기본 체크됨) ② **전달된 트래픽 수신 허용 — 기본은 해제되어 있으니 직접 체크하세요**. 아래 두 개는 게이트웨이 관련이라 그대로 둔 채 [추가]
6. **두 VNet 모두**에서 피어링 목록을 열어 상태가 "연결됨"인지 확인합니다. 새로 만드는 것이 아니라 **결과를 확인**하는 단계입니다 — 5번 한 번으로 양쪽이 이미 만들어졌습니다.
7. VM1에서 허브 쪽 리소스로 통신을 확인합니다. (Lab 4에서 본격 검증)

> 📷 **피어링 목록 — 상태 "연결됨"** — 양쪽 VNet 모두에서 피어링이 보이는지 확인합니다.
>
> 💡 **한 번에 양방향이 만들어집니다.** 2·3번에서 이름을 두 개 입력하는 것이 그 때문입니다. 추가 버튼을 누르면 허브에 `peer-hub-to-spoke-user**`, 스포크에 `peer-spoke-to-hub-user**` 가 각각 생깁니다. **반대쪽 VNet에 가서 또 만들지 마세요** — 예전 포털에서는 그래야 했지만 지금은 중복이 되어 오류가 납니다.
>
> ⚠️ **체크박스 네 개 중 ②는 기본이 꺼져 있습니다.** 「액세스 허용」하나만 체크된 채 넘어가기 쉬운데, 허브에 방화벽을 두는 이 구조에서는 **「전달된 트래픽 수신 허용」이 켜져 있어야** AWS·온프레미스에서 돌아오는 패킷을 스포크가 받아줍니다. 그런 패킷은 출발지가 두 VNet 어느 쪽에도 없는 주소라, 이 설정이 없으면 조용히 버려집니다.
>
> 아래 두 개는 **게이트웨이 관련**이라 지금은 켤 수 없습니다. 바로 앞 Task 2에서 배포를 걸었지만 **아직 끝나지 않았기 때문**입니다. **Lab 5 Task 1에서 배포 완료를 확인한 뒤 이 화면으로 돌아와 켭니다.** 이걸 안 켜면 터널이 붙어도 AWS에서 돌아오는 트래픽이 스포크를 찾지 못합니다.
