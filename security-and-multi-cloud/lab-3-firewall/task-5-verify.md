# Task 5 - 허용·차단 검증

규칙대로 동작하는지 실제 트래픽으로 확인합니다.

```bash
# ① 허용된 도메인 — 성공해야 함
curl -I https://archive.ubuntu.com

# ② 허용되지 않은 도메인 — 차단되어야 함
curl -I --max-time 10 https://www.google.com

# ③ 스포크 내부 통신 — 성공해야 함
ping -c 4 10.NN.9.5
```

1. VM1에 SSH로 접속합니다. — **접속이 안 되면 Task 3의 SSH 예외 경로(7~8번)를 빼먹은 것입니다.** 경로 테이블에 `내IP/32 → 인터넷`을 추가하면 바로 복구됩니다.
2. 위 명령을 순서대로 실행합니다.
3. 방화벽 → [모니터링] → 로그에서 허용·거부 기록을 확인합니다.
4. 차단된 요청이 로그에 남았는지 확인합니다.

- [ ] ① 허용 도메인 접속이 성공하는가
- [ ] ② 미허용 도메인이 차단되는가
- [ ] ③ 스포크 내부 통신이 되는가
- [ ] 방화벽 로그에 허용·거부 기록이 남는가

> ⚠️ ②가 성공해 버린다면 네트워크 규칙이 너무 넓게 열려 있는 것입니다. 「규칙 처리 순서」 — 네트워크 규칙에서 허용되면 애플리케이션 규칙은 평가되지 않습니다.
>
> 📷 **방화벽 로그 — 허용/거부 기록** — 차단된 요청의 대상 FQDN과 규칙 이름이 보이도록 캡처합니다.
>
> ⚠️ 로그가 안 보이면 ① Task 1에서 진단 설정을 켰는지 ② 켰다면 반영 지연(수 분) 순서로 확인하세요. 진단 설정 이전의 트래픽은 기록되지 않았으니 curl을 다시 실행하면 됩니다.
>
> 💡 **(선택) 시간이 남으면 직접 확인해 보세요.** Task 3에서 만든 SSH 예외 경로를 잠시 지우면 SSH가 바로 끊기고, 다시 추가하면 복구됩니다. 비대칭 라우팅을 30초 만에 체감할 수 있습니다.
>
> ⚠️ 확인했으면 **반드시 경로를 다시 추가**하세요. 빠뜨리고 넘어가면 Lab 5에서 또 막힙니다.
