# Lab 6 - Azure ↔ AWS 연결

이 과정의 도착점입니다. **Lab 5에서 만든 Azure 게이트웨이에 AWS를 연결**합니다.

> ⚠️ **이 Lab은 두 콘솔을 오갑니다.** 지금 어디에 있는지 놓치면 반드시 막힙니다. 각 Task 제목의 🟧(AWS 콘솔) / 🟦(Azure 포털) 표시를 확인하세요. 브라우저 탭 2개를 미리 열어두고 탭을 바꿔가며 진행하는 것을 권합니다.
>
> ⚠️ **이 페이지의 이름·대역은 예시입니다.** `10.**.x` → `10.내번호.x`, AWS VPC `172.16.**.0/24` → 내 대역 로 **바꿔서 입력**하세요.
>
> ❗ 이 Lab은 **대역을 서로 넣어주는 작업**이라 치환을 빼먹으면 바로 막힙니다. 특히 **Task 2의 정적 경로(= Azure 대역)** 와 **Task 3의 LNG 주소 공간(= AWS 대역)** 을 내 값으로 넣었는지 확인하세요.

## ★ 시작 전 필수 확인 — 이거 빼먹으면 터널이 UP이어도 ping이 안 됩니다

Lab 6은 앞 Lab의 설정이 전부 맞물려야 통신이 됩니다. **시작하기 전에 세 가지를 눈으로 확인하세요.** 특히 ①은 _이전 Lab 화면으로 되돌아가는 단&#xACC4;_&#xB77C; 가장 많이 빠집니다.

| #  | 확인할 것                                                             | 어디서                    | 빠지면 생기는 증상                                                                  |
| -- | ----------------------------------------------------------------- | ---------------------- | --------------------------------------------------------------------------- |
| ①★ | <p>피어링 게이트웨이 전송 두 체크박스<br>(허브 「전달하도록 허용」 → 스포크 「원격 게이트웨이 사용」)</p> | Lab 5 Task 1 「배포 완료 후」 | <p>터널 UP · 양방향 바이트도 증가 · 그런데 ping 실패<br>(돌아온 패킷이 스포크를 못 찾고 게이트웨이에서 버려짐)</p> |
| ②  | VPN 종류가 경로 기반, 활성-활성 사용                                           | Lab 3 Task 2           | 정책 기반이면 AWS 연결 자체가 불가 (45분 재배포)                                             |
| ③  | 게이트웨이 상태 성공 + 공용 IP 2개 메모                                         | Lab 5 Task 1           | Task 1의 CGW에 넣을 값이 없음                                                       |

* [ ] ★ 허브 피어링에 「전달하도록 허용」이 **켜져 있다**
* [ ] ★ 스포크 피어링에 「원격 게이트웨이 사용」이 **켜져 있다**
* [ ] 게이트웨이 상태가 「성공」이고 공용 IP 2개를 메모했다

## 콘솔 전환 지도와 값 전달 흐름

**어느 콘솔에서 무엇을 하나**

| Task | 콘솔       | 작업                          | 받아오는 값                   | 넘겨주는 값         |
| ---- | -------- | --------------------------- | ------------------------ | -------------- |
| 1    | 🟧 AWS   | VPC · 서브넷 · EC2 · VGW · CGW | ← Azure GW 공용 IP (Lab 5) | EC2 사설 IP      |
| 2    | 🟧 AWS   | S2S VPN 연결 생성               | —                        | 터널 외부 IP · PSK |
| 3    | 🟦 Azure | LNG 생성 + Lab 5 게이트웨이에 연결 추가 | ← 터널 외부 IP · PSK         | —              |
| 4    | 🟧🟦 양쪽  | 라우팅 · 보안 그룹 · 방화벽 · 통신 검증   | —                        | —              |

**값이 오가는 순서**

```
🟦 Lab 5에서 메모해 둔 것
   └ Azure GW 공용 IP  ─────────────┐
                                    ▼
🟧 Task 1  VPC·EC2 만들기 → VGW 만들고 VPC에 연결 → CGW 만들 때 [Azure GW 공용 IP] 입력
                                    │
🟧 Task 2  S2S VPN 연결 생성 (PSK 직접 지정)
        └ 결과로 나오는 것 : 터널 1 외부 IP  ·  PSK ──┐
                                                     ▼
🟦 Task 3  LNG 만들 때 [터널 외부 IP] 입력 → Lab 5 게이트웨이에 연결 추가 시 [PSK] 입력
                                                     │
🟧🟦 Task 4  양쪽 라우팅·보안 열고 ping ←───────────┘
```

> 💡 **메모장을 하나 열어두고 아래 4개 값을 채워가며 진행하세요.** 이 값들을 잃어버리면 되돌아가야 합니다.
>
> ```
> ① Azure GW 공용 IP  : __  (Lab 5에서 메모)
> ② AWS EC2 사설 IP    : __  (Task 1에서 확인)
> ③ AWS 터널 1 외부 IP : __  (Task 2에서 확인)
> ④ PSK               : __  (Task 2에서 직접 지정)
> ```
