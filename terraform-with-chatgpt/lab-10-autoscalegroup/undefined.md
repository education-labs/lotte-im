# 항목 설명

**Web SG가 CIDR 대신 ALB SG를 참조하는 이유**: Lab5에서 배운 "보안그룹 참조" 패턴이 여기서 실제로 쓰입니다. 인스턴스의 80번 포트를 `0.0.0.0/0`에 그대로 열어두면 누구나 ALB를 건너뛰고 인스턴스에 직접 접속할 수 있습니다. 소스를 ALB SG로 좁히면, "ALB SG가 붙은 리소스(=ALB)에서 오는 트래픽만" 허용되므로 반드시 ALB를 거쳐야만 웹서버에 닿을 수 있습니다.

**ALB가 2개 AZ의 서브넷을 필요로 하는 이유**: AWS ALB는 고가용성을 위해 최소 2개의 서로 다른 가용영역에 서브넷이 있어야 생성할 수 있습니다. 하나의 AZ에 장애가 생겨도 다른 AZ의 인스턴스로 트래픽을 계속 보낼 수 있게 하기 위한 강제 요구사항입니다.

**Target Group의 Health Check**: ALB는 등록된 인스턴스에 주기적으로 `health_check.path`(여기서는 `/`)로 요청을 보내 `matcher`에 지정한 상태 코드(`200`)가 오는지 확인합니다. 이 확인을 통과한 인스턴스(`healthy`)에만 실제 트래픽을 보냅니다. httpd가 아직 뜨지 않았거나 `index.html`이 없으면 `unhealthy`로 남아 트래픽을 못 받으므로, Step 3에서 반드시 상태를 확인해야 합니다.

**user\_data 안에서 Terraform 보간과 bash 변수가 충돌하는 문제**: Terraform의 heredoc(`<<-EOF ... EOF`)은 문자열 안의 `${...}` 패턴을 전부 Terraform 표현식으로 해석하려고 시도합니다. 그런데 bash에서 변수를 쓸 때도 `${HOSTNAME}`처럼 중괄호를 쓰는 경우가 많아, 그대로 두면 Terraform이 "그런 변수 없다"며 오류를 냅니다. 이 문제를 피하려면 bash 변수는 중괄호 없이 `$HOSTNAME`이나 `$(hostname)`처럼 쓰고, 진짜 Terraform 값만 `${aws_s3_bucket.assets...}`처럼 중괄호를 씁니다. ChatGPT가 만든 `user_data` 스크립트에 이 두 가지가 섞여 있으면 `terraform plan`에서 바로 오류가 나므로, 이번 Lab의 검증 포인트 중 하나로 넣었습니다.

**이미지가 인스턴스가 아니라 브라우저에서 직접 S3로 요청되는 구조**: `index.html`에는 이미지를 서버가 미리 내려받아두는 게 아니라 `<img src="https://.../banner.jpg">`처럼 S3의 퍼블릭 URL을 그대로 넣습니다. 즉 브라우저가 ALB를 통해 `index.html`을 받은 뒤, 이미지는 별도로 S3에 직접 요청합니다. 그래서 EC2 인스턴스에는 AWS 자격 증명이나 S3 접근 권한이 전혀 필요 없습니다(Lab7에서 버킷을 퍼블릭으로 설계해둔 이유가 바로 이것입니다).
